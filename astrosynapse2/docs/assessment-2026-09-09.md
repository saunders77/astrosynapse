# Astrosynapse 2: assessment and replacement experiments

Assessment started September 9, 2026; experiments continue on September 10 UTC.
Updated September 10 after the four-hour campaign and the user's clarification:
the immediate training objective is **successive improvements over the incumbent,
each independently verified at at least 95% confidence**. The 70% win rate against
the original champion is a longer-term benchmark, not a prerequisite for promotion.
**The requested 70% win rate has not been achieved.** The completed independent
test of the first replacement learner scored 52.05% in 1,024 games against the
global benchmark. This is insufficient evidence even of a small improvement.
No experimental checkpoint has been promoted into the application's registry.

**Architecture and code.** The champion has about 2.01 million parameters:
1,292 state features, 219 action features, a width-192 residual state trunk,
width-96 action representation, three residual blocks, and five policy/value
heads across eight decision families. The semantic encoder represents card
counts, zones, known information, in-play status, and state/action relations.
It avoids dependence on arbitrary hand/market indices. These are useful design
choices. There is no evidence yet that another factor of two in parameter count
would solve the plateau.

The callback engine separates public observations from hidden simulator state.
The existing arena swaps seats under common game seeds. The checkpoint and
database infrastructure preserve considerable experiment history. These parts
are worth retaining. The main replacements should target the behavior/loss
contract, credit assignment, the cost of inference, experiment control, and
statistical certification. A larger model trained by the same unsuccessful
operator would make the existing problem more expensive.

The original actor uses epsilon-greedy argmax choices, while its policy loss
optimizes a softmax distribution. Typical epsilon values are small, whereas
the underlying softmax remains diffuse. Clipping the chosen-action importance
ratio to two means rare alternatives can carry only a small effective mass.
For example, with target probabilities `[.4,.3,.3]` and behavior probabilities
`[.98,.01,.01]`, clipping produces effective weights `[.4,.02,.02]`, not the
target distribution. Even an action-independent advantage can then generate a
nonzero policy gradient. Correcting the chosen step alone also does not make
stale trajectories equivalent to trajectories under a changed policy. This is
a concrete objective mismatch, not evidence that importance sampling itself
is invalid. See the original [PPO paper](https://arxiv.org/abs/1707.06347) for the
fresh-policy clipped surrogate used by the replacement pilot.

The critic shares the actor's state representation. Value updates can therefore
change action rankings even when the actor signal is weak. Recent metrics
support concern about signal quality; they do not establish causality by
themselves. Medians below use each run's most recent 600 metric records where
the diagnostic is present:

Near-zero or negative agreement between independent gradient estimates is not
a healthy basis for millions more updates. In the mean-policy GAE snapshot,
normalized policy entropy is about 0.843 and gradient clipping is ubiquitous.
Turn-level advantages attached to every atomic action also spend learning
capacity on routine ordering choices that share essentially the same outcome.

**Search is not currently a reliable teacher.** Short reanalysis uses the same
critic that training is trying to improve. Small rollout budgets, noisy leaves,
and soft targets can reproduce critic mistakes or favor interchangeable action
orders. An independent stronger teacher has not been demonstrated. The
`reanalysis_fraction` implementation is per eligible MAIN decision, capped at
one sample per game. It is not a per-game sampling probability. At 100 eligible
decisions, a value of 0.0025 yields `1-(1-.0025)^100 = 22.1%` of games with a
sample, rather than 0.25%. Documentation describing the latter is misleading.

The new planner samples canonical public beliefs and resets future chance
streams. Merely shuffling an existing hidden simulator list with a fixed seed
does not guarantee that indistinguishable public positions produce the same
sampled world. Differential tests cover that property. Search should become a
training target only after a held-out tournament establishes that it improves
the frozen policy. This requirement follows the logic of
[Expert Iteration](https://proceedings.neurips.cc/paper_files/paper/2017/hash/d8e1344e27a5b08cdfd5d027d9b8d6de-Abstract.html);
the initial planner pilots here failed that requirement.

**Game fidelity.** The rules audit found two discrepancies: Explorers were
permanently scrapped, and ally abilities executed immediately instead of being
available for deliberate activation. Official rules return scrapped Explorers
to their supply and allow timing choices during the main phase. The
[official rulebook](https://files.wisewizardgames.com/starrealms/StarRealms_Frontiers_RuleBook2.pdf)
describes those rules; the [official FAQ](https://www.starrealms.com/faq/)
clarifies ally availability and other Core Set interactions. These errors can
distort strategy, but their contribution to the plateau has not been measured.

`GameConfig.rules_version=2` now provides corrected Explorer recycling and
explicit ally activation. Version 1 remains the historical default so existing
experiment identities do not silently change. New ally actions use the existing
semantic ability representation, with their effect and source card encoded.
Rules version and encoder version are separate concepts. Historical champions
have not trained on these new timing choices; their results under version 2
must be reported separately. The current learning pilots all use version 1.
The correction has dedicated official-rule example tests; this is not a claim
that every possible Core Set interaction has been exhaustively proved correct.

**Evaluation and experiment control.** The old adaptive promotion extension
repeatedly examined ordinary 95% intervals. `_extension_confidence` returned
0.95 regardless of the number of planned extension looks, and automatic-job
configuration reset it to 0.95. This is now fixed: the family error budget is
allocated across every possible extension boundary, including the original
boundary, with a separate reserved budget for early acceptance. Regression
tests now require the adjusted bounds and the larger necessary sample sizes.
Do not interpret a nominal interval after optional extension as a fixed-sample
95% certificate. Valid alternatives are fixed-size held-out tests or genuinely
[time-uniform confidence sequences](https://arxiv.org/abs/1810.08240).

The replacement experiments separate training seeds from evaluation seeds,
save immutable actor artifacts, and preserve paired game records. Screening
results are exploratory; choosing the best among many screens biases its
reported score upward. Final certification must freeze the entire player
(including any routine-policy component), use fresh seeds and a fixed sample
size, and adjust for testing multiple opponents. Treat truncations as candidate
losses, report each seat, and require a lower confidence bound of at least 70%
against both principal champions. A point estimate of 70% is insufficient to
demonstrate that the underlying win rate is at least 70%.

The first fresh-trajectory pilot trained on 10,240 games in about 521 seconds.
Its eight periodic screens ranged from 43.23% to 52.08%. It samples the exact
masked mean-head distribution used by its PPO loss, uses fresh terminal Monte
Carlo returns, and prevents critic gradients from moving the policy trunk.
The subsequent learner version measures full categorical KL rather than only
a sampled-action proxy. Stop/resume was verified against uninterrupted training:
the resulting parameters were identical in the small deterministic test.

Direct optimization of 104 public-information strategy coefficients also failed
to establish a breakthrough. The unrestricted two-generation pilot retained the
zero adapter. A six-generation strategic-only pilot selected a 52.86% screen
on 384 games; this was selection data, not independent confirmation.

A hierarchical pilot freezes the champion's routine behavior and trains only
strategic decision heads. It reduces recorded learning decisions from roughly
100 to 33 per game. It completed 30,720 games in about 21 minutes. Its best
screen scored 54.49%, but an independent 2,048-game test scored only 51.17%
(paired Hoeffding 95% interval 46.93–55.42%). Its player consists of both the learned actor and the frozen routine
actor. Loading the learned actor alone would evaluate a different player.

The subsequent four-hour managed campaign completed 311,296 training games:
65,536 each for strategic-head and strategic-full variants, and 180,224 for
full-policy learning. The first two branches were retired after four screens
without substantial progress. Full-policy screens reached 56.05%, with the
latest at 54.88%; these remain exploratory selection results. The 49,152-game
full-policy checkpoint is the starting candidate for the progressive run.

The progressive supervisor (`scripts/progressive_training.py`) runs one Metal
learner and eight CPU actors, screens every 8,192 training games, and verifies
promising candidates on fresh seat-swapped games. It uses a mixture of bounded
betting processes to produce a time-uniform lower confidence bound, following
the approach in [Waudby-Smith and Ramdas](https://arxiv.org/abs/2010.09686).
Candidate attempt k against a given incumbent receives error budget
`0.05 / (k * (k+1))`; the total over all attempts against that incumbent is at
most 5%. A promotion requires the lower bound to exceed 50%. This supports
optional stopping and small improvements without repeatedly inspecting ordinary
fixed-sample intervals. The guarantee applies to each incumbent's succession
test; it is not a simultaneous 95% guarantee for an unlimited chain of champions.

After promotion, the next learning stage starts from the accepted checkpoint
and its optimizer, trains against that new champion, and separately benchmarks
against the original champion. Incumbent-relative wins are not assumed to imply
transitive improvement. Models, seeds, code, paired records, and promotion
evidence are retained. Oversized updates restore both model and optimizer;
learning-rate adaptation now responds to the measured overall policy change
rather than treating an isolated minibatch stop as proof of excessive global KL.
Unscreened intermediate checkpoint files are pruned; evaluated checkpoints and
their optimizer states remain available. The dashboard at `/progressive` shows
actual saved state and provides safe pause/resume controls.

**Speed and hardware.** A native Accelerate implementation of the existing
actor removes repeated Python/NumPy dispatch. On this M4, a 32-game differential
run took 6.60 seconds versus 10.15 seconds for NumPy under concurrent load,
about 1.54 times faster. Winners matched; a separate 1,983-position comparison
had no greedy-action disagreements. Floating-point differences remain, so this
is empirical agreement, not a proof of bitwise equivalence. The native runtime
checks tensor shapes and finiteness and retains the original portable actor
format. It is macOS-specific. Pilots cap BLAS threads, use bounded actor caches,
and limit MLX cache memory to fit the current 16 GB machine.

**Recommended direction.** Retain the semantic encoder, portable artifacts,
public-state engine interface, and paired evaluation infrastructure. Replace
the unsuccessful behavior/loss combination and stop routinely spending tens
of thousands of games on near-tie candidates. Keep a modest fixed screen for
progress, dedicate most compute to learning, and reserve expensive independent
evaluation for substantial gains. Use a supervisor to enforce this allocation,
track policy KL, throughput, truncations, and reproducibility, stop regressions,
and preserve known-good candidates. A supervisor cannot manufacture a useful
gradient; adapting parameters without a measured learning signal merely
automates the existing plateau.

The next substantive tests are richer strategic policy learning with the fresh
objective, measured counterfactual supervision if a stronger planner can first
be established, and corrected-rules training as a separately identified domain.
Do not promote the present pilots or describe the infrastructure fixes as a
70%-strength solution. Continued experiments must earn that claim against the
frozen champions.
